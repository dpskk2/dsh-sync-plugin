# 优化决策与实施记录 · 2026-09-26

## 产品定位

以「换台电脑，继续同一个项目」作为主线。会话、附件、工作区文件一起迁移是现有实现能支撑的具体价值。README 先让读者识别使用场景，再给安装与验收步骤；内部合并算法留在深入文档。

## 本次实施

- README 中英文首屏改为品牌名、场景承诺、收益表和直接安装入口。
- 删除中文首屏「持续修 bug」横幅；维护反馈移到文末，首屏突出用户价值。
- 移走混合 Windows / Bash、全局 Git 代理的长段命令，保留排障入口。
- 安装与第二台接入分开，给出双向测试会话验收动作。
- 独立兼容性表保留 `engines.dsh` 最低宿主声明，区分包声明和真实验证记录。
- 调度器支持设置 API 保存后热切换；停止待执行活动计时器，卸载时清理资源。
- 设置返回实际生效配置，宿主覆盖时不假报所选模式已生效。
- 状态接口将工作区错误计为失败。
- 修复回归中发现的同秒备份分支重名，新增真实 Git 分支读回测试。

## 取舍

暂不把多云、AI 合并和凭据迁移揉进同一改动：这些涉及新的传输、冲突或信任模型，应独立设计与验收。现有数据合并规则保持原有语义。

README 的流程图明确为示意图，没有把设计稿充作真实截图。真实 GitHub 双机演示需要已登录的测试账号；本环境的本地 Git 多副本测试不能替代该证据。

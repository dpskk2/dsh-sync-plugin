# dsh-sync-plugin

DeepSeek Harness **会话同步插件**:通过自己的 GitHub 私有仓库,在**多台电脑之间双向同步 DSH 会话**,并同步每个会话所属工作区的**对应关系**(`storages/workspace.json` 里的「工作区→会话」映射)与各工作区**真实文件夹内容**(会话投影用的 `cwd` 就是它)。侧栏底部原生「⟳ 同步」按钮 + 设置面板「同步」状态卡。

> **v0.5 起只做「同步」**,专注于把「会话 + 工作区对应关系 + 工作区文件」稳定地在多台电脑间对齐;v0.7 起设置面板新增**「归档会话」管理处**(列出全部会话,含已归档/幽灵),可点击行**展开预览对话内容**、取消归档回到侧边栏或彻底删除。配置文件、本地 git 仓库与同步历史完全兼容旧版,直接升级即可。

## 安装/升级
安装:

```powershell
dsh plugin --profile web add dsh-sync-plugin
```

升级:

```powershell
dsh plugin --profile web update dsh-sync-plugin
```

也可以从 Git 仓库直接装(以包内 package.json 的 `name` 为准,目录/仓库名不影响):

```powershell
dsh plugin --profile web add github:dpskk2/dsh-sync-plugin
```

装完**重启 dsh**,侧栏左下出现「⟳ 同步」按钮(原生嵌入侧栏底栏,不再悬浮遮挡页面)。

> 前置:本机装好 [git](https://git-scm.com);推送/拉取 GitHub 需要 Git 凭据(`gh auth login` 或 Git Credential Manager 授权)。

## 界面在哪

- **侧栏底部「⟳ 同步」**:一键全量同步(提交 + 推送 + 拉取),结果以气泡提示;**保留 8 秒**再淡出,方便看清结果。
- **同步实时进度**:同步进行中,按钮文字实时变为当前阶段(取远端 / 提交 / 比对 / 拉取 / 合并 / 推送 / 工作区…),按钮上方有常驻进度气泡(阶段 + 已耗时);设置面板同步卡下方也有一行进度。阶段由引擎在每次 git 调用前上报,`/dsh-sync/api/progress` 每 0.5s 轮询一次。
- **设置 → 同步**(视觉与原生设置一致,无框无底色):只读状态卡(远端地址、分支、模式、工作区数、上次结果与**详细错误明细**)+ 右侧「立即同步」胶囊按钮。**上次结果会一直保留**在状态卡里,失败时以红色列出主数据错误与每个工作区的失败原因,便于排障。

## 首次配置(2 分钟)

- **手动**:在 GitHub 建一个**私有**仓库(如 `dsh-sync`),编辑 `~/.dsh/dsh-sync.json` 填入远端地址:

  ```json
  { "remote": "https://github.com/你的用户名/dsh-sync.git" }
  ```

  点一下「⟳ 同步」——首次会初始化本地 git 仓库并全量推送。完成。

- **自动建仓(需 gh CLI)**:本机装好 [gh CLI](https://cli.github.com) 并 `gh auth login`,配置里 `remote` 留空(默认 `autoRepo=true`),点一下「⟳ 同步」——插件会自动创建/复用你的**私有**仓库(默认名 `dsh-sync`,可在 `repoName` 改),把 `remote` 写回配置并全量推送。任何一步失败都退化为本地快照,不中断、不弄脏数据。

## 同步什么

| ✅ 同步 | ❌ 不同步 |
| --- | --- |
| 全部会话记录(`sessions/…/session.jsonl.zstd`)与附件 | **`.credentials.yaml`(API 密钥)——密钥永不上传**,换电脑重新登录即可 |
| **每个会话所属工作区的对应关系**:`storages/workspace.json`(工作区→`sessionIds` 映射)、`storages/session_projcache/sessions/<id>.json`(会话标题 / `cwd`)| `.anonymous-user-id`、`.dshw-size.json`、`.dshw-usage.json`、引擎自身临时状态 |
| **各工作区真实文件夹内容**(影子 git 仓库同步到远端 `ws/<工作区Id>` 分支);目标机缺该文件夹时自动创建 | `**/node_modules/`(依赖,`pnpm install` 复原)、`workspace-repos/`(工作区影子仓库) |

> 说明:会话投影缓存(`storages/session_projcache/`)其实**会同步**。它记录会话标题与 `cwd`,正是第二台电脑还原「工作区↔会话」对应关系所需;旧 README 写「可再生、不同步」与代码不符,以代码/本表为准。默认排除列表在 `~/.dsh/.gitignore`(首次同步时生成,手工改动会被保留)。

## 多台电脑

- **换电脑 / 新电脑**:装好 git + dsh 后(**先别启动 dsh**):

  ```powershell
  git clone https://github.com/你的用户名/dsh-sync.git "$env:USERPROFILE\.dsh"
  cd "$env:USERPROFILE\.dsh\profiles\web"; pnpm install
  ```

  启动 dsh——插件、配置、会话全部就位,按钮直接可用(密钥需重新登录一次)。首次点「⟳ 同步」会把各**工作区文件夹内容**(远端 `ws/<id>` 分支)一并拉下来,并在本机自动创建缺失的工作区文件夹,同时把 `workspace.json` 里的「工作区↔会话」对应关系还原。

- **日常**:哪台电脑用完点一下「⟳ 同步」,另一台开工前点一下,数据就接上了。**自动模式**(`mode=auto`)启动拉取 + 周期 + 对话结束后去抖。

- **同步不会意外覆盖**:引擎**永远先把本地变更提交**,再与远端比对/合并/推送;拉取用快进(`--ff-only`)。当两台电脑都改过:
  - 不同文件 → 自动合并(两边都保留);
  - **同一文件 → 「双边保留」**:本机版本保留为活动文件,远端版本另存为可见的 `<path>.dsh-conflict-<时间戳>` 拷贝,并把远端头备份到 `backup/<时间戳>` 分支——**任一方都不丢**,冲突呈现给你抉择(见下「冲突处理」);
  - 无共同历史的新仓库并入远端时,同名文件以远端为准,本地独有文件保留。

## 冲突处理(仿 OneNote:不丢任一方,呈现给用户抉择)

两台电脑同时改了**同一个文件**时,插件不会偏向任何一方,而是「双边保留」:

- **本机版本**保留为活动文件;
- **远端版本**另存为可见拷贝 `<原路径>.dsh-conflict-<时间戳>`(同目录,肉眼可见、可打开、可找回),并提交+推送,让另一台电脑也能看到它;
- 冲突出现在**设置 → 同步 → 冲突**分节(或 `sync_conflicts` 工具)里,列出每个冲突及两边版本位置,并提供三个按钮由你裁决:
  - **保留本机**:删除远端版本拷贝,把本机版本定为活动文件;
  - **采用远端**:用远端版本拷贝覆盖本机版本,定为活动文件(删除拷贝);
  - **两侧都留**:两者都保留(默认,不删拷贝)。

选定后插件立即提交并推送,其他电脑下次同步会拿到你的裁决。

> 为什么不做自动合并:会话日志是二进制 `.jsonl.zstd`,git 无法逐行合并;即便对 `workspace.json` 这类文本,自动「保留一方」也可能让你丢掉刚写的数据。「双边保留 + 你裁决」才是 OneNote 式的做法:宁可先都留着,再由你决定。

## 工作区文件夹同步

DSH 的「工作区」对应一个真实磁盘文件夹(会话投影的 `cwd` 及 `workspace.json` 里的 `path` 都是它)。插件把它也一起同步:

- **影子 git 仓库,不碰你的真实文件夹**:每个工作区的 git 元数据放在 `~/.dsh/workspace-repos/<工作区Id>.git`,通过 `core.worktree` 指向真实文件夹。**真实文件夹里不会出现 `.git`**,所有 git 操作都在 `.dsh` 管控区里完成。
- **内容自动对齐**:同步时以真实文件夹为工作树提交变更,与远端 `ws/<工作区Id>` 分支快进/推送/合并;不同电脑交替使用即可接上。
- **目标机缺文件夹 → 自动创建**:在远端把工作区内容拉下来时,若本机没有对应文件夹,插件会先自动创建它,再物化内容。
- **跨机路径**:若记录的是 `C:\Users\<某用户>\Documents\聊天`,插件会尝试把它重映射到**本机主目录**下对应的 `Documents\聊天`(换电脑/用户名也能对上)。也可用 `workspaceBase` 把所有工作区统一放到某个目录下(按文件夹名)——**跨机建议配置** `workspaceBase` 让两机路径一致。

## 配置(`~/.dsh/dsh-sync.json`)

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `manual` | `manual` 纯手动(点按钮才同步);`auto` 自动(启动拉取 + 周期 + 对话结束后去抖) |
| `enabled` | `true` | 仅在 `mode=auto` 时作为总开关(手动按钮不受它限制) |
| `remote` | `''` | GitHub 私有仓库地址;留空则只做本地快照(免费版本历史) |
| `branch` | `main` | 同步分支 |
| `commitMessage` | `dsh-sync-plugin: auto snapshot` | 快照提交信息 |
| `intervalSeconds` | `300` | (auto)周期兜底 |
| `eventDebounceSeconds` | `15` | (auto)对话结束后的去抖延迟 |
| `minCommitIntervalSeconds` | `120` | (auto)提交节流;**手动触发(按钮 / 设置面板 / CLI)不受限**,点一下立刻提交 |
| `autoRepo` | `true` | 首次同步(`remote` 为空)时,自动创建/复用 GitHub 私有仓库;设 `false` 关闭,改回手动填 `remote` |
| `repoName` | `dsh-sync` | 自动使用的仓库名(仅 `autoRepo` 且未配置 `remote` 时生效) |
| `repoOwner` | `''` | 仓库所属用户名;留空则取 `gh` 登录账号 |
| `repoDescription` | `''` | 自动创建仓库时的描述(可选) |
| `workspaceSync` | `true` | 是否同步工作区文件夹内容(完整备份/恢复;目标机缺文件夹自动创建) |
| `workspaceBranchPrefix` | `ws` | 工作区分支前缀 → `ws/<工作区Id>` |
| `workspaceBase` | `''` | 可选:所有工作区统一映射到该目录下(按文件夹名),用于跨机路径不一致 |
| `workspaceExtraIgnore` | `['node_modules']` | 工作区内容额外排除(目录名;`.git` 恒排除);写入影子仓库 `info/exclude`,不碰真实文件夹 |

## 命令行(不打开 dsh 也能同步)

```powershell
node "%USERPROFILE%\.dsh\profiles\web\node_modules\dsh-sync-plugin\lib\cli.mjs"
```

(可选:把桌面快捷方式指向它。结果打印到控制台并**保留**,便于排障。)

## 补丁管理(node_modules 补丁跨机分发)

DSH 内置包(如 `@deepseek-ai/dsh-web-fetch-http`)的修复不能直接改在 `node_modules`
里——依赖目录不随同步仓库走(`.gitignore` 排除),DSH 升级还会整体覆盖。
v0.8 起插件把这类补丁做成**随主仓库同步的托管补丁**,每台机器启动/同步后自动重新套用:

- 补丁放 `~/.dsh/patches/<名字>/`(天然入库、跨机同步):`patch.json` 清单 +
  完整目标文件作为 `payload`;
- 清单字段:`name` / `package`(目标 npm 包)/ `target`(包内相对路径,如 `lib/index.js`)/
  `payload`(补丁文件名)/ `packageVersion`(录制时的包版本,不符则不盲写,标 `needs-refresh`)/
  `marker`(补丁标记,检测旧版补丁并升级)/ `enabled`;
- 应用时机:启动时、每次同步后、CLI 手动同步后、`sync_patches` 工具 / 设置状态卡手动触发;
- 状态:已是最新 / 已应用 / 已更新(套用后**重启 dsh 生效**)/ 已还原 / 上游已升级待重录;
- 还原:首次套用前会把原始文件备份成 `original-*` 放在补丁目录里,删除 `payload` 前可用它还原。

内置补丁:`web-fetch-http`(web_fetch 直连失败自动回退系统代理 + 瞬态错误重试 + 报错显示真实根因)。

## v0.9 工作区对应关系跨机还原(会话不再"落到未分组")

把「会话 ↔ 工作区」的对应关系真正随同步走,而不是只同步 `workspace.json` 这个文件本身:

- **登记表自动修复**:每次同步前,插件按**真实会话文件**重算归属——每个会话从日志头读出所属 `cwd`,
  补进对应工作区的 `sessionIds`;缺失的工作区条目自动补建(只增不改,不碰宿主编排)。
  DSH 自己有时会把 `workspace.json` 的 `sessionIds` 写空(重建登记表),修复让映射始终跟得上。
- **workspace.json 冲突并集合并**:两机同时改动登记表时不再「单边保留」,而是合并双方工作区与会话映射,
  各自电脑上的工作区都保留、两边都归组。
- **归档列表跨机显示修复**:会话分组文件夹名(`--C-Users-...-~XXXX~--`)按 DSH 同款编码还原,
  并按规范化路径(统一盘符冒号/分隔符、忽略大小写)与 `workspace.json` 比对,
  不再显示 `C-Users-tanos-Documents-dsh-聊天` 这类原始串,而是显示工作区标题(如 `聊天`)。
- **目标机操作**:拉到新数据后**重启一次 DSH**(侧边栏按新登记表归组);工作区文件夹(即使内容为空)
  会由同步自动在目标机创建,DSH 校验会话 `cwd` 落位需要它存在。

## v0.9.1 会话删除真正生效 + 机器本地配置不再被覆盖

- **删除/取消归档立即上云**:操作后马上提交并推送登记表,不再等下次同步;
  另一台电脑拉取后,并集合并会按「本机或云端是否存在会话文件」自动剔除已删除的登记——
  **幽灵会话(无文件的登记)会被自动清理,删掉的会话不会"复活"**。
- **`settings.yaml` 不再同步**:它是机器本地配置(含第三方 provider 的密钥引用,如 `apiKeyEnv`),
  之前会被拉取覆盖导致本机 apikey/配置被"清空";现已从仓库剔除(真正的密钥在
  `.credentials.yaml`,本来就不同步)。目标机第一次拉到这个版本后,DSH 会按默认值重建
  `settings.yaml`,需要重新填一下 provider 配置。
- **空工作区不再报"同步失败"**:内容为空的工作区(如还没有文件的文件夹)跳过推送,
  目标机仍会自动创建该文件夹(DSH 会话归组校验需要它存在)。

## v0.9.2 会话内容自动合并 + 冲突可视化裁决 + 工作区跨机落位提示

- **两机同时改同一会话不再"复制打架"**:会话日志(`session.jsonl.zstd`)冲突时,插件把两侧日志
  各自解压,按**事件时间**交错合并(共同基线去重),重排 `seq` 并重映射 `sourceEventSeqs` 引用,
  校验通过后写回 —— **电脑1新增的几句会直接出现在电脑2的同一个会话里**,而不是变成 `.dsh-conflict`
  拷贝。任何一步无法验证(格式异常/引用缺失/无法压缩)自动退回「双边保留」,绝不产出 DSH 读不了的日志。
- **冲突列表带原标题 + 两侧预览**:「冲突」分节每条显示会话原标题(不再是一串路径);点「预览两侧」
  可并排查看**本机版本**与**远端版本**各自的消息(标题/条数/最近 60 条),看清再裁决保留哪一侧。
- **工作区跨机落位提示**:同步后发现目标机原本没有某工作区文件夹、已按本机主目录自动重映射创建时,
  设置面板出现「本机新创建的工作区」横幅(记录路径 → 实际路径),可一键**换位置**(写入本机专属
  路径覆盖,不随同步走)或**恢复默认**。同一用户名(路径天然一致)的两台电脑无需任何操作,静默落位。
- **已知边界修正**:会话日志冲突现在按内容自动合并;仍走「双边保留」的只有无法安全合并的极端情况
  (一侧删除另一侧修改、日志损坏、旧 Node 无 zstd 压缩)或非会话文件。

## v0.9.3 投影缓存冲突不再打扰你

- **`session_projcache/**`(会话投影缓存)冲突自动处理**:它是 DSH 读会话时自动重建的
  可再生缓存,不该占用你的裁决 —— 同步时这类冲突直接取本机版本;已有的冲突拷贝在下一次
  同步时**自动删除并推送**,不再出现在「冲突」分节。
- 万一还挂着(升级前产生的),冲突列表会给它标注**「会话投影缓存(可再生)」**并显示
  所属会话标题,点「保留本机」即可,下次同步自动清理。
- **安装/升级修复**:profile 的 pnpm 锁文件曾把插件钉在 0.8.0,导致 `dsh plugin update`
  显示"Already up to date"却升不上去;本机已改为 `^0.9.2` 并安装 0.9.3,以后 update 正常。

## 已知边界(如实说明)

- **两机同时改同一会话**:v0.9.2 起按内容自动合并(见上节);只有无法安全合并时才「双边保留」——本机版本保留,远端版本另存为 `.dsh-conflict-<时间戳>` 拷贝,并把远端头备份到 `backup/<时间戳>` 分支。在「冲突」分节(带标题与两侧预览)或 `sync_conflict_resolve` 里裁决;日常想完全避免冲突,错开使用、用完即同步即可。
- **跨机用户名不同**时,`workspace.json` 记录的仍是源机绝对路径;插件会对工作区文件夹做主目录重映射,但会话日志头部记录的 `cwd` 仍为源机路径。建议在两机配置 `workspaceBase` 指向**同一目录名**,让路径完全一致。
- 会话附件(`attachments/`)是按内容寻址的共享存储,同步后不会重复。
- **工作区文件夹同步的边界**:位于用户主目录之外的工作区(如 `D:\…`),跨机恢复时按记录的绝对路径创建(无法自动换盘符);工作区里**嵌套的 git 仓库**(如 `plugin-src/` 自带 `.git`)会被**自动排除**,不随工作区同步——其内容由各自仓库自行管理/备份(否则父仓库会把它们登记成 gitlink,嵌套仓库一有改动父仓库提交就失败)。**DSH home 本身(`.dsh`)不当作工作区文件夹同步**——它已由主仓库覆盖,避免循环/带上密钥与 `node_modules`。
- **同步性能**:每个仓库的 fetch 只取自己那条分支(不再把主仓库 main 的会话历史拉进每个工作区仓库——那会让工作区仓库膨胀到几十 MB 且每次都重复下载);fetch/push 遇到网络瞬时抖动(schannel 握手失败)自动重试一次;多个工作区**并行**同步,互不等待。
